# House of Ketty

The House of Ketty website: a store, the story behind the brand,
and contact details, in English, Thai (`/th/`) and Hindi (`/hi/`).

Customers choose a product and a design, then send the order on WhatsApp. They
pay by UPI or in cash. There is no checkout, database or server code: the site
is plain HTML, CSS and a little JavaScript, generated by a small Node build.

## Everyday changes

Everything you would normally edit is in `src/`. Push to `main` and the site
rebuilds and deploys (see [Deploying](#deploying)).

| To change | Edit |
| --- | --- |
| Products, prices, photos | `src/data/products.json` + `src/images/products/` |
| Categories | `categories` in `src/data/products.json` |
| WhatsApp numbers, UPI ID, domain | `src/data/site.json` |
| Story episodes | `src/content/story/{en,th,hi}/epNN.txt` + `src/data/episodes.json` |
| Any other wording | `src/i18n/en.json`, `th.json`, `hi.json` |
| Colours, fonts, layout | `src/styles/main.css` |

### Add a product

1. Put the photos in `src/images/products/` with a clear name, such as
   `silk-scarf-1.jpg`. Phone photos are fine: the build resizes them and
   creates fast AVIF and JPEG versions.
2. Add an entry to `products` in `src/data/products.json`. Copy an existing
   one. Every product needs a `summary` and every photo needs `alt` text in
   **all three languages**. The tests fail if one is missing.
3. Set the price in one of these shapes:
   - Exact price: `"price": { "amount": 599 }`. The customer sees the total
     and can pay the exact amount by UPI.
   - Several prices: `"price": { "tiers": [ { "amounts": [299, 399, 499] } ] }`
   - A range: `"price": { "tiers": [ { "min": 499, "max": 699 } ] }`
   - "From": `"price": { "tiers": [ { "label": { "en": "Watch", "th": "นาฬิกา", "hi": "घड़ी" }, "from": 399 } ] }`
   - Ask for price: `"price": null`
4. If each photo is a different design the customer can pick, add
   `"pickDesign": true`. Add `"featured": true` to show it on the homepage.

**Before uploading photos**, remove location data. Phone cameras store GPS
coordinates in photos, and the old site published them. The build strips
metadata from what it publishes, and `npm test` fails if a photo in
`src/images/` still has it. After adding photos, run `npm run clean-photos`.
It strips metadata, fixes rotation and converts PNG/HEIC/WebP to JPEG (update
the file name in `products.json` if it changed).

### Turn on the UPI QR code

Until a UPI ID is set, the site tells customers the UPI ID is shared on
WhatsApp. To show the UPI ID, a copy button, a scannable QR code and a
"Pay ₹599 in a UPI app" button on exact-price products, do one of these:

- set `"upi": { "id": "yourname@okaxis" }` in `src/data/site.json`, or
- set a repository **variable** named `UPI_ID` in GitHub (Settings → Secrets
  and variables → Actions → Variables).

A UPI ID is safe to publish: it can only receive money.

## Working on the site

Needs Node 22 (`nvm use`).

```bash
npm install
npm run dev        # http://localhost:4321, rebuilds when src/ changes
npm test           # data, translations, contrast, security and build checks
npm run build      # writes dist/
npm run a11y       # axe WCAG 2.2 AA on every page + real browser flows (after build)
```

`npm run a11y` needs a Playwright browser once: `npx playwright install chromium`.

### How it fits together

```
src/data/        products, episodes, site settings (JSON)
src/i18n/        every UI string, one file per language
src/content/     story episodes as plain text, one paragraph per block
src/images/      source photos (metadata-free)
src/styles/      one stylesheet; colour tokens per page theme
src/scripts/     shared.js (prices, WhatsApp/UPI links; used by build and
                 browser) and main.js (menu, bag, filters, gallery)
build/           the static site generator
test/            node:test suites; test/browser/ drives Chromium
```

Pages work without JavaScript. The script adds the bag, filters, and exact
WhatsApp messages on top.

## Accessibility

Targets WCAG 2.2 AA, and `npm test` plus `npm run a11y` check it on every
build:

- Every colour pair in every page theme is contrast-checked from the CSS.
- axe-core runs on all 72 pages, desktop and mobile, with no violations.
- Keyboard: skip link, visible focus rings, Escape closes menus and the bag,
  and focus returns where it came from. Targets are at least 44px.
- Proper `lang` on every page and on the language switcher's links, and
  translated `alt` text for every photo.
- Parallax and all animation turn off under "reduce motion".

## Security

- **No third-party code.** Fonts, scripts and images are self-hosted. There
  are no trackers or embeds, and no cookies.
- **Strict Content-Security-Policy**: `default-src 'none'`. Scripts come only
  from this site, plus one inline line allowed by its hash. There are no
  inline styles or event handlers, and the tests enforce it.
- **Headers** (`dist/.htaccess`, generated by `build/security.mjs`): HSTS,
  `X-Content-Type-Options`, `X-Frame-Options: DENY` / `frame-ancestors 'none'`,
  `Referrer-Policy`, a locked-down `Permissions-Policy`, COOP/CORP. It also
  forces HTTPS, disables directory listing, allows only GET/HEAD, and blocks
  dotfiles and backups.
- **Visitor input** (name and note in the bag) is length-limited, stripped of
  control and text-direction characters, and only ever URL-encoded into a
  wa.me link. It is never inserted as HTML. The saved bag is checked against
  the product list on every read, so tampered data is dropped.
- **Photos** carry no EXIF/GPS metadata, and a test enforces it.
- **CI**: GitHub Actions pinned to commit SHAs, read-only token by default,
  `npm audit` on every run, and Dependabot for npm and Actions.
- `/.well-known/security.txt` says where to report a problem.

## Deploying

`.github/workflows/deploy.yml` runs on every push and pull request. It runs
`npm audit`, the tests, the build and the browser checks. On `main` it also:

1. **GitHub Pages**, which serves https://ksommaketarin-droid.github.io/sk-official/.
   GitHub Pages ignores `.htaccess`, so there the CSP and referrer policy
   come from each page's `<meta>` tags. The other headers apply only on
   Hostinger hosting.
2. **Hostinger production**, once switched on.

### Switch on automatic deploys to Hostinger

1. In hPanel → **Files → FTP Accounts**, note the FTP host, username and
   password (or create an FTP account limited to `public_html`).
2. In GitHub → Settings → Secrets and variables → Actions:
   - **Secrets**: `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`
   - **Variables**: `HOSTINGER_DEPLOY` = `true` (and optionally `UPI_ID`,
     and `HOSTINGER_DIR` if the site is not in `./public_html/`)
3. Re-run the workflow, or push to `main`.

The upload uses FTPS with certificate checking. If it fails with a TLS error,
set `FTP_SERVER` to the exact hostname hPanel shows for FTP.

In hPanel, also check that **SSL** is active for the domain, and that it
points at this hosting plan.

### Deploy by hand

```bash
npm ci && npm run build
```

Then upload the **contents** of `dist/` into `public_html/` with hPanel's File
Manager. Include the hidden `.htaccess` and `.well-known/`.

Old links (`/ep01.html` … `/ep08.html`) redirect to the new story pages.
